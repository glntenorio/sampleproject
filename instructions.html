0Words you will see

Developers use a handful of odd words for simple ideas. Here they are in plain language. Each one is explained again when it first comes up, so you do not need to memorise this list.

Repository, or repo
A project folder. The one for this site holds a few web pages and a stylesheet. A copy lives on GitHub and, once you set up, another copy lives on your computer.
Fork
Your own copy of someone else's project on GitHub. You can change it freely without touching the original.
Clone
Downloading a project from GitHub onto your computer so you can open the files.
Commit
A saved checkpoint of your changes, with a short note saying what you did. Think of it as "save, with a label".
Push
Uploading your commits from your computer to GitHub.
Pull, or sync
The opposite of push: bringing the latest version from GitHub down to your computer.
Branch
A separate line of work inside a project, so you can try something without disturbing the main version. The main version is called main.
Pull request
A polite request to the project owner: "please take my changes into the original". The owner reviews them and merges them in.
Deploy
Putting the site on the internet so it has a public web address. Vercel does this for you automatically.
Terminal
A window where you type commands instead of clicking. You only need it twice in this guide, and the exact text to type is given each time.
Command Palette
A search box inside VS Code that runs any action by name. Open it with Cmd+Shift+P on Mac or Ctrl+Shift+P on Windows.
Extension
An add-on for VS Code that gives it an extra feature, like a browser add-on.

1Create your accounts

You need two free accounts.

  1. GitHub stores the code. Sign up at github.com/signup.
  2. Vercel publishes the site. Go to vercel.com/signup and choose Continue with GitHub. Pick the free Hobby plan.

Signing up to Vercel with GitHub matters. It lets Vercel see your copy of the project without any extra setup later.

2Install Git and VS Code

Git

Git is the program that keeps track of your changes and sends them to GitHub. GitHub is the website; Git is the tool on your computer that talks to it.

Installing it means using the terminal, a window where you type commands. Do not worry, the exact text to type is given below and you only need it here and in step 3.

  • Mac: open the Terminal app (search for it with Spotlight), type git --version and press Enter. If Git is not installed, macOS offers to install it. Click Install.
  • Windows: download and run the installer from git-scm.com/download/win. Accept all the defaults.

Check it worked. Open a new terminal (Mac: Terminal, Windows: Git Bash from the Start menu) and run:

git --version

You should see a version number.

VS Code

VS Code is the program you will edit the files in, like Word but for code. Download it from code.visualstudio.com and install it.

Then add one extension (an add-on that gives VS Code an extra feature). Click the Extensions icon in the left sidebar (four squares), search for Live Server by Ritwick Dey, and click Install. This previews the site with automatic refresh.

3Tell Git who you are

Git labels every change with a name and email. Set them once, using the same email you used for GitHub:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

4Make your own copy (a fork)

A fork is your personal copy of the project on GitHub. You can change anything in it without affecting the original.

  1. Open github.com/glntenorio/sampleproject/fork.
  2. Leave everything as it is and click Create fork.

You now have your own copy at github.com/YOUR-USERNAME/sampleproject.

If you were given push access to the main repo, you can skip the fork and use github.com/glntenorio/sampleproject in the next step instead. Accept the invitation email from GitHub first.

Not sure whether you have push access?

On your own fork you always do, because it is your copy. On the main repo, here is how to tell:

  • Try the pencil. Open any file on the main repo and click the pencil icon. If you have access it edits in place. If not, GitHub says You need to fork this repository to propose changes and makes a fork for you. Either way you can still make the change; it just lands in a different place.
  • Look for a Settings tab. It only appears at the top of the repo page for people with write access.
  • Check your email. Push access comes with an invitation from GitHub that you must accept. No invitation, no access.

When in doubt, use a fork. It always works and nothing is lost.

5Get it onto your computer (clone)

Your fork lives on GitHub's website. To edit the files you need a copy on your own computer. Downloading that copy is called cloning. VS Code can do it for you.

  1. Open VS Code.
  2. Open the Command Palette, a search box that runs any VS Code action by name: Cmd+Shift+P on Mac, Ctrl+Shift+P on Windows.
  3. Type Git: Clone and press Enter.
  4. Paste the URL of your fork, for example https://github.com/YOUR-USERNAME/sampleproject.git, and press Enter.
  5. Choose a folder to put it in, such as Documents, and click Select as Repository Destination.
  6. When asked, click Open.

The first time, VS Code asks you to sign in to GitHub. Click Allow and follow the browser prompts. This only happens once.

You should now see the project files in the left sidebar: index.html, playground.html, an assets folder and so on.

6See the site locally

Option A, recommended: in VS Code, right-click playground.html in the sidebar and choose Open with Live Server. Your browser opens the page. Every time you save, it refreshes on its own.

Option B: find the folder in Finder or Explorer and double-click playground.html. Refresh the browser yourself after each save.

7Make a change

  1. In VS Code, click playground.html to open it.
  2. Find the line near the top that starts with <h1> and change the text.
  3. Press Cmd+S (Mac) or Ctrl+S (Windows) to save.
  4. Look at the browser. The heading has changed.

The Playground page lists five things to try, from changing a colour to editing JavaScript.

8Save it to GitHub (commit and push)

Saving a file only changes it on your computer. Getting it onto GitHub takes two small steps. A commit is a checkpoint: it bundles your changes together with a short note about what you did. A push uploads those commits to GitHub. VS Code has buttons for both.

  1. Click the Source Control icon in the left sidebar. It looks like a branch and shows a number when you have changes.
  2. Hover over Changes and click the + to stage all your files.
  3. In the Message box, type a short note like Change playground heading.
  4. Click Commit.
  5. Click Sync Changes (or Publish Branch the first time).

Refresh your fork on GitHub and you will see the change and your message.

9Publish on Vercel

You only do this once. After that, every push republishes automatically.

  1. Go to vercel.com/new.
  2. Find sampleproject in the list and click Import. If you do not see it, click Adjust GitHub App Permissions and allow access to the repository.
  3. Leave every setting alone and click Deploy.
  4. After about a minute you get a link to your live site. Open it and add /playground to the end.

From now on, every push republishes your site within a minute. Check the Version label in the footer to confirm you are seeing the latest build.

10Get the latest updates

When a new version is released, your fork does not update by itself.

  1. On GitHub, open your fork. Above the file list you will see something like This branch is 3 commits behind. Click Sync fork, then Update branch.
  2. In VS Code, open Source Control and click Sync Changes to bring it down to your computer.

Vercel republishes your site automatically. The footer version should now match the latest entry in the changelog.

If GitHub reports a conflict, we both changed the same lines. Only click Discard commits if you are fine losing your changes to that file. Otherwise, send a note and we will sort it out together.

11Send changes back (pull request)

Your changes so far live only in your fork. A pull request is how you ask for them to be taken into the original project. It opens a page on GitHub where the change can be discussed, previewed and then merged in.

  1. Open your fork on GitHub.
  2. Click Contribute, just above the file list, then Open pull request.
  3. Give it a title, fill in the short template, and click Create pull request.

The change gets reviewed and merged. Once merged, use Sync fork from step 10 to bring it back into your copy. A pull request also gets its own preview link, so the change can be seen live before merging.

If you have push access instead of a fork: create a new branch (a separate line of work so your change does not disturb the main version) in VS Code (click the branch name in the bottom-left corner), commit, click Publish Branch, then use the Compare & pull request button GitHub shows you. The main branch is protected, so all changes go in through pull requests.

12Report a bug or give feedback

Please report on the main repository, not on your fork, so everything lands in one place.

  1. Go to the new issue page.
  2. Choose Bug report for something broken, or Feedback for ideas.
  3. Fill in the template. Screenshots help a lot. You can drag an image straight into the text box.
  4. Click Submit new issue.

13Undo mistakes

You cannot really break anything. Some common rescues:

ProblemFix
I changed a file and want it back the way it wasIn Source Control, hover the file and click the Discard Changes arrow.
I want to throw away everything since my last commitCommand Palette, type Git: Discard All Changes.
I committed something bad and have not pushedCommand Palette, type Git: Undo Last Commit.
My copy is a mess and I want a fresh startDelete the folder from your computer and repeat step 5. Your GitHub fork is untouched.
Even my fork is a messDelete the fork on GitHub (Settings, bottom of the page, Delete this repository) and fork again from step 4.
